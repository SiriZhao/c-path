# Getting started

C·Path is designed for the first session to be short and concrete: read one problem, write a small C program, run it, and inspect the result.

## Your first exercise

1. Open the [online workspace](https://sirizhao.github.io/c-path/).
2. Choose **Start practicing** or open **Hello, C·Path!** from the featured list.
3. Read the statement and examples before editing `main.c`.
4. Put input into the custom input box when the program reads stdin.
5. Run the current program, then run the samples.
6. Submit local tests after the output matches the examples.
7. Use the next-exercise link to continue while the idea is still fresh.

## How to read a result

- **Compilation error** means the source did not produce a program. Read the diagnostic and check the indicated line.
- **Runtime error** means the program started but failed while running.
- **Time limit exceeded** usually means a loop did not reach its stopping condition.
- **Local tests passed** means this browser execution matched the configured tests. It is not a hidden server verdict.

Drafts, progress, favorites and review markers stay in the current browser. Export the progress file before clearing site data or changing devices.

## When the first run is slow

The C runtime is downloaded lazily on first use. Keep the tab open while it initializes. Later runs use the browser cache. A blocked runtime host or unsupported browser is reported as unavailable; C·Path never substitutes a preset output.
